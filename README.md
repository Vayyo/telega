# 📨 Telega

Telegram-клиент для Linux на Rust, iced и TDLib. Для входа нужны собственные Telegram API ID и API hash.

## ✨ Возможности

| Область | Что есть в клиенте |
| --- | --- |
| 🔑 Аккаунты | Вход по телефону или QR-коду, несколько слотов аккаунтов; в плавающем меню — фото всех аккаунтов из локального кэша, имя и выход с подтверждением |
| 💬 Общение | Чаты, вкладки по всей ширине окна, поиск сообщений с догрузкой, папки и архив, ответы, пересылка, реакции; боты помечены `Bot` рядом с именем в списках, чатах и участниках группы; полупрозрачное меню действий открывается поверх сообщений, не сдвигая ленту |
| 🎞️ Медиа | Просмотр фото, воспроизведение видео и видеокружочков с перемоткой, раскрытием и отдельной сохраняемой громкостью для каждого сообщения; управление кружочком показывается при наведении; воспроизведение аудио |
| 🗃️ Локально | Архив **увиденных** удалённых сообщений, Lua-плагины |

Это **не замена Telegram Desktop с полным набором функций**: звонки, истории, экспорт данных и полноценные настройки приватности не реализованы. Архив не восстанавливает сообщения, которые клиент не видел, и не хранит историю правок. Часть действий проверялась только в офлайн-песочнице, а не на живом аккаунте; работа с реальным аккаунтом не подтверждена полноценным тестированием.

При выборе чата и закрытии всплывающей панели фокус возвращается в поле сообщения; открытое меню или поиск не пропускают ввод в черновик. Настройки разделены на независимо раскрываемые категории: «Общие», «Сообщения», «Оформление», «Хранилище», «Безопасность», «Плагины». Состояние раскрытия сохраняется до смены аккаунта или перезапуска.

В главном окне папки находятся в узкой левой колонке: иконки с подписями, выбранная папка и счётчики непрочитанного. При переполнении прокручиваются только папки, нижняя кнопка «Настройки» остаётся доступной и открывает управление их порядком. Во вкладках чатов показаны мини-аватарки; без фотографии — инициалы. В обычном окне список чатов сохраняет прежнюю ширину, в узком сжимается, оставляя место кнопкам ввода; отдельные окна сохраняют компактный вид.

Кнопки ввода используют кешированные графические иконки: улыбка, бумажный самолётик, скрепка и микрофон; при редактировании самолётик заменяется галочкой. Текст локального закрепления и статуса печати в списке чатов контрастен и на выбранной строке.

В истории сообщений удерживайте ЛКМ на свободном фоне и тяните рамку через нужные сообщения. Внутри текста перетаскивание по-прежнему выделяет символы. Двойной клик ЛКМ по сообщению сразу включает ответ; движение мыши вместо второго клика отменяет ответ. Выделение не открывает меню: нажмите ПКМ по выбранному сообщению, чтобы копировать, переслать или удалить весь набор. Escape или одиночный клик ЛКМ по пустому фону истории снимает выделение.

MP4-GIF воспроизводятся внутри чата: при занятых трёх декодерах ждут освобождения места, явный клик имеет приоритет над автоматическим воспроизведением. Лимиты автоматической загрузки — 10 МиБ для GIF и 1 МиБ для анимированных стикеров; уже скачанное медиа не отсекается по размеру, большую GIF можно запустить кликом. Для фотографий в профилях групп и пользователей используется большой файл TDLib и отдельный 256 px кэш в памяти; маленькие аватарки и их дисковый кэш остаются 64 px.

## 🧰 Перед сборкой: TDLib и ключи

Нужны Rust stable (edition 2024), Git, CMake, Clang, gperf, заголовки OpenSSL и zlib, `pkg-config`, `libclang`, библиотеки разработки для FFmpeg, ALSA, Wayland/XKB и D-Bus. Для Ubuntu список пакетов есть в [CI](.github/workflows/ci.yml). `scripts/build-tdlib.sh` скачивает из GitHub исходники закреплённого коммита TDLib 1.8.67 и собирает библиотеку. При нехватке памяти используйте `JOBS=2 scripts/build-tdlib.sh` (по умолчанию — 4 задачи).

Скрипт применяет закреплённые патчи TDLib для проверки TLS при DNS-over-HTTPS и запрета небезопасного DNS-fallback у прокси с логином/паролем. После обновления репозитория пересоберите TDLib тем же скриптом: существующая `libtdjson` не обновляется при одной лишь сборке Rust.

Получите собственные `api_id` и `api_hash` на [my.telegram.org](https://my.telegram.org/apps). **До сборки** скопируйте шаблон и заполните `TG_API_ID` и `TG_API_HASH` в `.env`:

```sh
cp .env.example .env
```

Вместо `.env` можно задать переменные в окружении при сборке. `build.rs` **встраивает ключи в бинарный файл**; при запуске переменные окружения имеют приоритет над встроенными. Не публикуйте `.env` **или собранные бинарные файлы с ключами**, не добавляйте их в коммиты: исключение `.env` из Git не защищает уже собранный файл.

## 🚀 Быстрый старт

Из корня репозитория после настройки ключей:

```sh
scripts/build-tdlib.sh
cargo build --locked
cargo run --locked
```

TDLib устанавливается скриптом в `third_party/tdlib`; `.cargo/config.toml` указывает на эту библиотеку, а Cargo использует исправленный `vendor/tdlib-rs`. Для запуска библиотека и собранный репозиторий должны оставаться на месте.

На Linux закрытие главного окна оставляет клиент работать в трее: чаты и черновики остаются в памяти. Вернуть окно можно кликом по значку или пунктом «Открыть Telega»; завершить клиент — пунктом «Выход». Вторичные окна чатов закрываются отдельно. Если сервис значка не удалось инициализировать, закрытие главного окна завершает клиент. Панель должна поддерживать StatusNotifierItem (например, KDE или waybar с треем).

При закрытии прекращаются запись микрофона и воспроизведение видео, принадлежащие главному окну; видео другого окна остаётся нетронутым.

## 🔒 Данные и ограничения безопасности

Данные аккаунта лежат в `~/.local/share/telega` (или `$XDG_DATA_HOME/telega`); непустая переменная `TELEGA_DATA_DIR` меняет этот путь. Не запускайте два экземпляра с одним каталогом данных.

Необязательный **локальный** пароль (не облачный пароль Telegram) шифрует базу TDLib и текст архива удалённых сообщений. Скачанные файлы и база плагинов `plugins-{account_id}.sqlite` **не шифруются** этим паролем. Локальные уведомления могут показывать имена и текст сообщений. Выход из аккаунта не гарантирует очистку всех его локальных архивов и баз плагинов: перед передачей устройства проверьте каталог данных. Не устанавливайте непроверенные Lua-плагины.

Для нового локального пароля требуется минимум 12 символов; ранее созданные короткие пароли по-прежнему принимаются при разблокировке. Это не защита от вредоносного ПО или доступа к уже разблокированному клиенту.

Смена локального пароля сохраняет journal восстановления до изменения ключей. После прерывания операция возобновляется вперёд: при смене подходит старый или новый пароль, при включении — новый, при отключении — старый. До завершения запрещены переключение/выход/сброс аккаунта и добровольное закрытие клиента; не понижайте версию при незавершённом recovery. Ошибка checkpoint/VACUUM после commit показывается как предупреждение, а не вызывает обратную смену ключа.

Пароль не гарантирует физического стирания свободных страниц SQLite, WAL, backup или snapshots. Открытые metadata/ID не шифруются; новые текстовые кэш-наблюдения, отложенные на время rekey-worker, могут потеряться при аварии. Точные границы памяти, journal и worker — в [описании исправлений](docs/security-fixes-2026-10-02.md).

Имена прокси с логином/паролем разрешаются только через `dns.google` по HTTPS с проверкой сертификата; при недоступности сервиса подключение к такому прокси не выполняется. Числовой адрес прокси не требует DNS. Google при таком разрешении видит имя прокси. Для прокси без логина/пароля остаётся штатная политика DNS TDLib; она не даёт той же гарантии конфиденциальности имени.

В разделе «Настройки → Хранилище» задаются пределы размера (1–100 ГиБ, по умолчанию 10 ГиБ) и срока хранения (1–12 месяцев по 30 дней, по умолчанию 3 месяца). Для скачанных файлов TDLib эти пределы действуют **отдельно для каждого аккаунта**; TDLib может исключать из очистки фото профиля, стикеры, миниатюры и обои. Это не точный предел всего каталога: базы данных, архив и плагины в него не входят. Очистка TDLib происходит при очередном обслуживании, не сразу после изменения настройки; удалённое медиа при следующем показе может скачаться заново.

Декодированные аватарки кэшируются в открытом виде в `<каталог данных>/avatars/` под хэшем исходных байтов. Для общего для всех аккаунтов кэша действует **отдельный** предел того же размера и срока; очистка выполняется при запуске, после изменения настройки и периодически. Выход из аккаунта сам по себе не очищает этот каталог.

Оперативная память ограничена отдельно от дисковых пределов. Неактивная вкладка главного окна выгружает подтверждённую историю через 5 минут после ухода с неё: черновик, ответ, редактирование, выделение, пересылка и неотправленные сообщения сохраняются, а позиция чтения (сообщение и смещение внутри строки) восстанавливается при возврате повторной загрузкой с сервера. Вторичные окна чатов держат историю, пока открыты. Изменения, пришедшие к выгруженной вкладке, накапливаются не более чем на страницу (50 ID) и проверяются одной выборкой по известным ID; непрерывные посторонние правки не мешают показу. Декодированные изображения живут в общем бюджете 64 МиБ: невидимое освобождается сразу, а без обращения истекает через 5 минут. Скачанные файлы и база TDLib этим не затрагиваются — их пределы задаются в разделе «Хранилище».

Если загрузка истории выгруженной вкладки или переход к сообщению прервались ошибкой сети, повторный клик по активной вкладке запускает новый запрос; прежний поздний ответ не заменяет актуальную историю.

## 🧪 Офлайн-проверки

```sh
cargo test --locked --all-targets
bash scripts/security-observer-probe.sh
cargo clippy --locked --all-targets -- -D warnings
cargo fmt --all -- --check
```

Обычные тесты, включая `tests/tdlib_smoke.rs` и `tests/tdlib_encryption.rs`, используют **локальную TDLib** без входа в аккаунт и без собственных API-ключей. Это не проверка реального входа, синхронизации и серверных ограничений. Для строгой изоляции сети на Linux: `unshare --user --map-current-user --net cargo test --locked --all-targets` (с сохранением обычного UID). Для снимков интерфейса без аккаунта: `cargo test --bin telega sandbox -- --ignored` (результат в `target/sandbox/`; по умолчанию эти тесты пропускаются). В GitHub Actions TDLib собирается и все проверки, включая standalone native runner, выполняются без `.env` и входа в Telegram. При падении тестов аннотация GitHub Actions показывает ограниченную сводку из последних 3500 байт вывода.

CI кэширует только `third_party/tdlib` по точному ключу платформы и хэшу `scripts/build-tdlib.sh` и `scripts/security/tdlib-*.patch`: смена закреплённого коммита, скрипта или патчей инвалидирует кэш. Первый запуск с новым ключом — холодная сборка; все проверки выполняются и при попадании в кэш.

Обработчики событий чата, обновления TDLib и боковая панель выделены в `src/app/pane_update.rs`, `src/app/td_updates.rs` и `src/app/sidebar_view.rs`; координация окон и фокуса остаётся в `src/app.rs`. [Аудит 2026-10-01](docs/security-audit-2026-10-01.md) описывает исторические наблюдения; все 14 пунктов и аудиопауза исправлены в v0.3.0. [Результаты и ограничения](docs/security-fixes-2026-10-02.md), [ADR-011](docs/adr/011-recoverable-key-and-async-security-boundaries.md), [release notes](docs/releases/v0.3.0.md).

Текущий [аудит безопасности 2026-10-04](docs/security-audit-2026-10-04.md) перечисляет исправления, проверки и непроверенные сценарии; решение по границам асинхронных ответов и DNS прокси — в [ADR-014](docs/adr/014-client-bound-async-and-proxy-dns.md). Исправления этого аудита и срез состояния — в [release notes v0.4.0](docs/releases/v0.4.0.md).

## 🖥️ Запуск из меню Linux

```sh
cargo build --release --locked
scripts/install-desktop.sh
# Удалить запись меню, значки и симлинк:
scripts/install-desktop.sh --uninstall
```

Установщик создаёт пользовательский симлинк `~/.local/bin/telega`, значки и запись в меню приложений (с учётом `$XDG_DATA_HOME`). Перед запуском проверьте скрипт, если симлинк или запись с таким именем уже существуют. Для работы симлинка и поиска TDLib оставьте собранный репозиторий на месте.
