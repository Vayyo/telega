# Telega

Десктопный клиент Telegram на Rust для Linux (iced + TDLib). Для запуска аккаунта нужны собственные API ID и API hash Telegram.

## Возможности и ограничения

В коде есть вход по телефону/QR, несколько слотов аккаунтов, чаты, поиск сообщений с догрузкой, папки и архив, ответы/пересылка/реакции, просмотр фото и базовое воспроизведение видео/аудио, локальный архив **увиденных** удалённых сообщений и Lua-плагины. Это не полный аналог Telegram Desktop: звонки, истории, экспорт данных и полноценные настройки приватности здесь не реализованы; локальный архив не восстанавливает сообщения, которых клиент не видел, и не ведёт историю правок. Некоторые действия проверялись только офлайн в песочнице, не на живом аккаунте.

## Сборка и запуск

Нужны Rust stable (edition 2024), Git, CMake, Clang, gperf, заголовки OpenSSL и zlib, `pkg-config`, `libclang` и системные библиотеки разработки для FFmpeg, ALSA, Wayland/XKB и D-Bus. На Ubuntu зависимости устанавливаются тем же списком пакетов, что в [CI](.github/workflows/ci.yml). Скрипт сборки TDLib клонирует исходники и скачивает закреплённый коммит TDLib 1.8.67; для этого нужен доступ к GitHub. При нехватке памяти задайте `JOBS=2` (по умолчанию скрипт использует 4 параллельные задачи).

Получите свои `api_id` и `api_hash` на [my.telegram.org](https://my.telegram.org/apps). Скопируйте `.env.example` в `.env` и заполните `TG_API_ID` и `TG_API_HASH` **до сборки**: `build.rs` встраивает их в бинарный файл. Можно вместо `.env` задать эти переменные в окружении при сборке; переменные окружения при запуске имеют приоритет над встроенными значениями. `.env` исключён из Git, но ключи из собранного бинарного файла тоже не следует публиковать. Не добавляйте `.env` в коммиты.

```sh
scripts/build-tdlib.sh
cargo build --locked
cargo run --locked
```

Скрипт размещает библиотеку в `third_party/tdlib`; `.cargo/config.toml` указывает на неё, а Cargo использует исправленный `vendor/tdlib-rs`. При запуске собранного клиента библиотека должна оставаться в репозитории.

Данные аккаунта по умолчанию хранятся в `~/.local/share/telega` (или `$XDG_DATA_HOME/telega`); путь можно переопределить непустой переменной `TELEGA_DATA_DIR`. Не запускайте два экземпляра на одном каталоге данных.

## Безопасность и защита данных

Необязательный **локальный** пароль (не облачный пароль Telegram) шифрует базу TDLib и текст архива удалённых сообщений. Скачанные файлы и база плагинов `plugins-{account_id}.sqlite` **не шифруются** этим паролем; локальные уведомления могут показывать имена и текст сообщений. Выход из аккаунта не гарантирует очистку всех его локальных архивов и баз плагинов: перед передачей устройства проверьте каталог данных. Не устанавливайте непроверенные Lua-плагины.

## Проверки

```sh
cargo test --locked --all-targets
cargo clippy --locked --all-targets -- -D warnings
cargo fmt --all -- --check
```

Обычные тесты, включая `tests/tdlib_smoke.rs` и `tests/tdlib_encryption.rs`, запускают **локальную библиотеку TDLib** без входа в аккаунт и без необходимости в собственных API-ключах. Это не тест реального входа, синхронизации или серверных ограничений; при требовании строгой изоляции сети запускайте тесты в сетевой песочнице. Для генерации снимков интерфейса без аккаунта запустите `cargo test --bin telega sandbox -- --ignored` (результат в `target/sandbox/`); тесты песочницы по умолчанию пропускаются. В GitHub Actions сборка TDLib и проверки выполняются без `.env` и без входа в Telegram.

## Установка в меню приложений

```sh
cargo build --release --locked
scripts/install-desktop.sh
# Удалить запись меню, значки и симлинк:
scripts/install-desktop.sh --uninstall
```

Установщик создаёт пользовательский симлинк `~/.local/bin/telega` на релизный бинарный файл и запись в меню приложений (с учётом `$XDG_DATA_HOME`); проверьте скрипт перед запуском, если у вас уже есть запись или симлинк с этим именем. Для работы симлинка и поиска TDLib оставьте собранный репозиторий на месте.
