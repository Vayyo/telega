# 006. Фотографии всех аккаунтов в меню переключения

Дата: 2026-10-01

## Решение

Сохранять в настройках каждого авторизованного аккаунта необязательный BLAKE3-адрес его декодированной фотографии. Само изображение остаётся в общем дисковом кэше аватарок из [ADR-001](001-keep-downloaded-files-and-avatar-cache.md), с ограничениями [ADR-002](002-configurable-cache-limits.md). При запуске загружать доступные фотографии из этого кэша, а при переключении сохранять дескрипторы в памяти приложения вне сменяемой TDLib-сессии. Если записи кэша нет, показывать инициалы до получения фотографии в активной сессии.

Появление или смена файла фотографии повторно запускает датчик видимости аватара: загрузка остаётся ленивой, невидимые контакты не скачиваются. Для обновлений своего профиля, полученных до `my_id`, идентифицировать аккаунт по сохранённому `user_id` активного слота. При удалении фотографии сбрасывать её адрес и дескриптор; запоздалый результат декодирования от прежнего TDLib-клиента игнорировать.

## Почему

Смена аккаунта уничтожает текущую TDLib-сессию с фотографиями контактов. Сохранять только файл TDLib или дескриптор в сессии недостаточно: строка неактивного аккаунта после переключения и перезапуска иначе остаётся с инициалами. Общий контентный кэш уже хранит готовые круглые изображения без привязки к `file_id` и аккаунту; дублировать пиксели в настройках или отдельном каталоге не нужно.

## Следствия

- Удаление записи при уборке кэша даёт инициалы до очередной загрузки в активном аккаунте; сохранённый адрес не мешает правилам очистки.
- У старых настроек нет поля адреса: необязательное поле имеет значение по умолчанию, миграция не требуется.
- Меню не делает запросов в TDLib неактивного аккаунта. Изменение его фотографии на другом устройстве станет известно после следующего открытия этого аккаунта.
