# 003. Закрытие главного окна оставляет клиент в трее

Дата: 2026-09-30

## Решение

На Linux запрос закрытия главного окна закрывает только нативное окно, оставляя процесс, TDLib, главный pane, чаты и черновики. Клик по значку/пункту «Открыть Telega» или уведомлению восстанавливает окно под прежним iced `window::Id`. Пункт «Выход» завершает процесс. Вторичные окна закрываются обычным образом; без инициализированного сервиса трея закрытие главного окна остаётся выходом. Запись микрофона главного окна при его закрытии отменяется.

## Почему

Клиент должен получать сообщения в фоне после закрытия окна. В текущем winit 0.30.13 `set_visible` на Wayland не реализован: `Mode::Hidden` не скрывает поверхность. Закрытие и повторное создание нативного окна работают на Wayland; прежний логический ID сохраняет адресацию pane и асинхронных ответов.

## Отвергнутые альтернативы

- Завершать процесс при закрытии — противоречит запрошенному фоновому поведению.
- Использовать `Mode::Hidden` — пустая операция на Wayland.
- Выдавать новый ID и переносить оконное состояние — пришлось бы переносить и все адресованные старому окну асинхронные операции.

## Следствия

- Используется публичный `iced_runtime::window::Action::Open` с сохранённым ID; `iced_runtime` перенесён из dev-зависимостей в обычные без изменения версии.
- Состояния `Open`, `Closing`, `Hidden`, `Opening` предотвращают дублирующее создание; активация во время закрытия ждёт подтверждения `Closed`.
- Изменённые настройки сохраняются при закрытии главного окна и явном выходе. Создание нативного окна заново не равно перезапуску клиента или входу в аккаунт.
- При подтверждённом закрытии главного окна его видеоплеер освобождается вместе с декодером и чтением TDLib; видеоплеер другого окна не затрагивается.
- Нужна панель с поддержкой StatusNotifierItem; инициализация сервиса сама по себе не доказывает наличие видимого значка в панели.
