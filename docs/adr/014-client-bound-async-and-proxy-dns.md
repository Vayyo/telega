# 014. Привязка асинхронных ответов к клиенту и DNS прокси

Дата: 2026-10-04.

Решение: ответы асинхронных TDLib-запросов истории, профиля, ссылок, файлов и связанных действий применять только к клиенту, запустившему запрос; ответ истории дополнительно сверять с текущими окном, чатом и номером запроса. При ошибке загрузки выгруженной вкладки оставлять её состояние для нового запроса по явному клику на выбранной вкладке. Новые локальные пароли требовать длиной не менее 12 символов, прежние короткие принимать для разблокировки. Сброс аккаунта после ошибки удаления его данных останавливать без стирания ключевой metadata.

Решение для нативной сети: собирать закреплённую TDLib с воспроизводимыми патчами: проверять сертификат DoH, не переходить по HTTP-перенаправлениям, для имён прокси с логином/паролем использовать только проверенный HTTPS DNS без системного fallback. Из DoH принимать только числовые A/AAAA; при отсутствии AAAA разрешён отдельный HTTPS-запрос A. Числовой адрес прокси подключать без DNS. Прокси без учётных данных сохраняют штатную политику TDLib.

Почему: прежний ответ другого клиента мог отображаться и попадать в архив активного аккаунта; поздняя страница того же чата могла заменить новую. Ошибка сети оставляла выгруженную активную вкладку пустой без повторного запроса. У DoH TDLib была отключена проверка сертификата, native fallback и разрешение CNAME через системный DNS позволяли подменить адрес прокси и передать его логин/пароль чужому узлу.

Отвергнутые альтернативы: определять источник ответа только по chat_id; бесконечно повторять ошибочную загрузку автоматически; доверять ответу DoH без TLS или числовой проверки; после сбоя DoH использовать незащищённый системный DNS для прокси с паролем. Следствия: при недоступном `dns.google` имена таких прокси не работают, оператор DoH видит имя прокси; локальные IP не требуют DoH. Это не защищает от скомпрометированного доверенного CA/DoH, вредоносного сервера прокси, доступа к разблокированному клиенту или от ошибочных асинхронных путей вне перечисленных запросов. Решение дополняет [ADR-011](011-recoverable-key-and-async-security-boundaries.md) и [ADR-013](013-inactive-tab-and-media-memory.md).
