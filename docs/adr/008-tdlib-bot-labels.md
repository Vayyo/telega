# 008. Метка Bot по типу пользователя TDLib

Дата: 2026-10-01

## Решение

Показывать `Bot` рядом с именем пользователя-бота в сообщениях групп, списке участников группы и карточке пользователя, а для личных чатов с ботом — в списках чатов, вкладках, заголовке и профиле. Для уже известных пользователей признак берётся из `UserType::Bot` в `updateUser` и хранится на время работы аккаунта по ID пользователя; для списка участников — из ответа существующего `getUser` при загрузке профиля. Перед показом ответа профиля тип сверяется с уже полученными `updateUser`, поэтому запоздалый ответ не возвращает прежнюю метку; новые `updateUser` обновляют открытый профиль. Личный чат связывается с пользователем по `ChatType::Private.user_id`, не по ID чата. Обновление пользователя может прийти до или после чата; смена типа на обычного пользователя убирает метку. В узкой панели длинное название обрезается перед меткой и индикаторами непрочитанного/выключенного звука.

## Почему

Тип пользователя и связь личного чата уже передаёт TDLib. Метка по этим данным не зависит от имени, языка, порядка обновлений и совпадения ID пользователя с ID чата.

## Отвергнутые альтернативы

- Определять ботов по имени, `@username` или суффиксу `bot`: возможны ложные срабатывания и боты без такого имени.
- Использовать ID чата как ID пользователя: TDLib не гарантирует их равенства.
- Записывать тип бота в `settings.json`: после изменения типа данные устареют; TDLib сообщает актуальное состояние при запуске.

## Следствия

- Если тип собеседника ещё неизвестен ни из `updateUser`, ни из данных профиля, метка не показывается; данные другого аккаунта при переключении не используются.
- Это оформление существующих чатов и участников, без дополнительных запросов к сети, хранения персональных данных на диске и изменения формата настроек.
