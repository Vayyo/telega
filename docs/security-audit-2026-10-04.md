# Аудит безопасности telega — 2026-10-04

Область: текущий рабочий каталог Rust GUI, vendored `tdlib-rs`, закреплённая TDLib 1.8.67 (`42e6a5259551178d1dab54a22ad96d14bd906e20`), локальные данные, сеть, медиа и плагины. Репозиторий до аудита уже содержал пользовательские незакоммиченные изменения; эта проверка не сравнивает приложение с опубликованной версией. Высокая оценка для прокси условна: в просмотренном UI нет настройки прокси; атака требует уже настроенного через TDLib прокси с логином и паролем.

## Короткие фрагменты исправлений на Rust

```rust
// История принимается только от того же клиента и действующего запроса:
if client != self.session.client_id
    || !pane.shows(chat_id)
    || pane.history_request != Some(request)
    || pane.cold.is_some()
{
    return Task::none();
}
pane.history_request = None;
```

```rust
// Не подавляем первое сохранение сообщения, которое ещё не лежит в архиве:
let updated = statement.execute(params![chat_id, id, stored])?;
if updated != 0 {
    self.remember(chat_id, id, text.to_owned());
}
// Не доверяем сумме смещения и длины от внешнего форматирования:
let end = entity.offset.checked_add(entity.length)?;
```

`VerifyPeer::On` и запрет DNS-fallback реализованы в TDLib на C++; один Rust-фрагмент не может исправить ошибку нативного резолвера. Воспроизведение нативных патчей требует `JOBS=2 scripts/build-tdlib.sh`; одна лишь пересборка Rust не обновляет существующую `libtdjson`.

## Подтверждённые положительные границы

- MTProto не реализуется заново в GUI: TDLib проверяет `msg_key` и длину/паддинг (`td/mtproto/Transport.cpp`), `session_id`, время и повтор `msg_id` (`AuthData.cpp`, `SessionConnection.cpp`), DH-параметры/nonce и серверные ответы (`DhHandshake.cpp`, `Handshake.cpp`). Это статическая проверка указанных функций, не формальная криптографическая экспертиза TDLib.
- Локальный ключ: `getrandom` для соли/nonce, Argon2id, XChaCha20Poly1305 AEAD, `Zeroizing` для Rust-owned секретов; Unix 0700 для каталога, 0600 для файла настроек, атомарная запись с fsync. TDLib секретные JSON-буферы Rust очищаются на границе FFI; чужие копии в GUI/SQLite/OS не гарантированы.
- Изображения ограничены по размеру декодирования, FFmpeg открывает разрешённые форматы/протоколы, Luau запускает исходник в песочнице с бюджетами, внешние ссылки ограничены web/mail. Метаданные/ID, скачанные файлы, база плагинов и кэш аватаров не зашифрованы локальным паролем.
- `Cargo.lock` фиксирует checksum registry-зависимостей, TDLib закреплена по commit. API ID/hash из `.env` по замыслу встраиваются в бинарник при сборке; ни `.env`, ни этот бинарник публиковать нельзя.

## Реальные проверки и пределы

- Сначала регрессионные тесты падали на правильной причине: overflow entity; UPDATE 0 строк; сброс после ошибки и короткий PIN; чужая история/устаревшая страница/Unlock; повтор выгруженной вкладки, stale edit/deletion при jump, пропуск newer-страницы и archived tail. После правок адресные тесты зелёные. Старое утверждение о строке ошибки «4» удалено как несовместимое с новой политикой, а полезный тест несовпадающих паролей использует допустимую длину.
- `JOBS=2 scripts/build-tdlib.sh`: TDLib `tdnet`, `tdcore`, `tdjson` пересобраны из исправленных исходников, команда завершилась успешно. `unshare --user --map-current-user --net cargo test --locked --all-targets --quiet`: 439 passed, 32 ignored, 0 failed, плюс два локальных интеграционных теста TDLib прошли. `cargo fmt --all -- --check` и `unshare ... cargo clippy --locked --all-targets -- -D warnings` прошли. `unshare ... bash scripts/security-observer-probe.sh`: 4 passed. Изолированные headless UI-сценарии `sandbox_password` и `sandbox_memory_reclamation` прошли; отрисованные PNG осмотрены.
- `unshare --user --map-current-user --net cargo build --release --locked`: optimized release-сборка завершилась успешно за 1 мин 27 с. Встроенные при сборке API ID/hash означают, что этот бинарный файл нельзя публиковать.
- Нативный DoH-сценарий под настоящим сетевым посредником, реальный Telegram-аккаунт/пользовательский прокси и пароли не использовались. Сборка + локальные тесты доказывают компиляцию патча и запуск TDLib, но не сетевую эксплуатацию/её устранение в живой сети; нативный путь проверен статически независимым ревью. Если `dns.google` недоступен, credentialed hostname-прокси не подключится; сам DNS-запрос выдаёт имя прокси Google.
- `cargo audit`/`cargo deny` в окружении отсутствуют, новые системные инструменты без отдельного разрешения не устанавливались: сканирование RustSec/CVE **не проведено**. `cargo tree --locked --offline -d` и `cargo metadata --locked --offline` не заменяют advisory scanner. Не проверены ACL на Windows, утечки через snapshot/WAL/свободные страницы, копии секретов в нативной памяти, лимиты для чрезмерных mini-thumbnail/waveform и полная reachability повреждённых TDLib entity. Нельзя заявлять об отсутствии всех CVE или всех уязвимостей.
